# Architecture Documentation Guidelines

本目录是 Jcode 的 mdBook 架构解读文档集。这里的文档面向想理解技术设计的读者，而不是项目规划读者、进度跟踪读者或市场介绍读者。

## Writing Perspective

- 从读者视角出发：读者关心的是技术设计、核心抽象、边界划分与取舍原因。
- 不把叙事重点放在“长期目标”“当前阶段”“已有实现很少”等项目状态描述上。
- 不写宣传式、路线图式或愿景式表达；必要时可以说明边界，但必须服务于技术理解。
- 不把章节写成源码清单；优先解释代码背后的结构、职责与不变量。

## Content Focus

每篇文档优先回答以下问题：

1. 这个设计解决了什么架构问题？
2. 核心抽象是什么，它们如何协作？
3. 为什么边界要这样切？
4. 哪些约束或不变量不能被破坏？
5. 这个设计放弃了什么复杂度或能力？

## Style Rules

- 正文使用中文，代码标识符、模块名、类名、协议名保留英文原名。
- 使用“技术解读”语气：清晰、克制、解释性强，避免口号化。
- 避免频繁使用“当前”“未来”“规划”“目标是对齐”等词作为主叙事。
- 可以提到未展开的模块或能力，但只作为架构边界或分层关系说明。
- 对 pi 的引用只允许作为设计参照或背景材料，不要把文档写成 pi 的功能对照表。
- 章节之间保持递进：总览先建立坐标系，专题章节再展开机制细节。

## mdBook Conventions

- 正文文件放在 `src/` 下。
- 新增章节必须同步维护 `src/SUMMARY.md`。
- 文件名使用数字前缀和英文 kebab-case，例如 `04-streaming-model.md`。
- `README.md` 只说明文档系统使用方式；读者入口内容放在 `src/index.md`。
